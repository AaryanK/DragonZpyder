# DragonZpyder: Frontier Stress Round 1 — measured evidence

**Date:** 2026-11-07  
**Branch:** `chore/lean-platform-cleanup-20261107` (draft PR #33, staging only)  
**Suite:** `api/agent_platform/evals/frontier_stress_v1.json`  
**Outcome:** **No frontier-parity claim.** No case has a verified end-to-end successful live-model run.

## Objective

Test ten unrelated, difficult long-horizon tasks requiring independent analysis,
parallel specialists, artifact creation, interruption handling and objective
verification. Suite contains ten cases and **5,205 prompt words** across ten
distinct domains. The tasks are original; they are not copied from any official
frontier benchmark and cannot be directly equated to published leaderboard
scores.

## Evidence collected

1. **GitHub Actions agent-stack:** After adding adversarial evaluator tests,
   `agent-stack-imports` recorded **59 passed in 4.09s** on branch commit
   `ba4b28316e3d5da2f8eeeeb5136c732a328e3a4f`.
   Workflow run: https://github.com/AaryanK/DragonZpyder/actions/runs/42385411443
   The workflow invokes `python -m agent_platform.frontier_stress` and
   `pytest ... tests/test_frontier_stress.py` and calls each long prompt
   through a **scripted fake model**. This proves prompt acceptance, graph
   construction, and code wiring, **not problem-solving ability**.
2. **Staging F08 real-model canaries:** DragonZpyder Agent Test Lab logs
   around 15:05–15:13 UTC show `status=execution_failed`,
   `objective_verified=false` and `tools=0`. Gateway logs show:
   - 15:05:17 UTC: invalid model tool-call format;
   - 15:08:05 UTC: tool-call arguments were not JSON;
   - 15:13:20 UTC: upstream provider returned HTTP 404, relayed by gateway as HTTP 502.
   A later previously-recorded failure logged 502. These are *failures*,
   not successful benchmark completions. The record does not establish
   whether provider model availability, provider-specific formatting,
   request parameters or another upstream issue caused the 404.
3. **Evaluator hardening:** `frontier_stress.py` no longer trusts
   `report.objective_verified` as the outcome oracle; a separate, case-keyed
   oracle must be supplied by a trusted caller. Expected artifacts must match
   **exact** virtual paths, not basenames in unrelated workspaces.
   The accidental F02 `0.005` artifact was corrected (it is a numeric
   tolerance requirement, not a file). Adversarial tests verify these gates.
   A caller-supplied oracle object is not cryptographic attestation;
   live evaluation still needs authenticated, independently computed judges.

## Next experiments, in strict order

1. **Provider integration root cause:** Use the existing staging gateway and
   permitted model catalog. Confirm selected model has a tool-capable endpoint;
   classify provider 404 separately from malformed JSON tool-call responses.
   Add a bounded, no-side-effect model+tool-response smoke. Do **not** silently
   repair corrupt JSON into different function arguments or bypass permission checks.
2. **Real canary:** With explicit operator budget and request ceiling,
   run **F08 once**, capture sanitized per-call traces and metered cost, verify
   actual `write_file` and `read_file` events and inspect artifact bytes.
   A fluent final answer alone earns zero outcome credit.
3. **True parallelism:** Instrument per-agent timestamps, distinct subagent IDs,
   failed/cancelled spans and shared dependency edges. Compare a controlled
   sequential-delegation baseline against parallel delegation. No overlapping
   spans means no parallel credit.
4. **Environment-based oracles:** Install isolated sandbox execution, a
   full-page research provider, independent judges and reversible fixture data.
   Require authenticated outcome receipts with artifact checksums and a
   clear trust boundary separate from the model output.
5. **Ten-case trial:** Hold model/tool/step/token budgets constant, conduct
   at least three fresh attempts per case, including injected failures.
   Compare with a frontier model on the **identical** task fixtures and
   judge, recording success, partial checkpoints, retries, p50/p95 time,
   user interventions, total metered USD, and cost per verified success.

## Promotion decision

**NO-GO for frontier equivalence.** The harness passes offline integration
checks, but the first genuine real-model canary failed at the provider/tool
gateway before meaningful task execution. Prioritize model-tool protocol
reliability, independent outcome grading and actual concurrent execution
before spending on the remaining nine long tasks.

This report changes no production system, sends no email, buys nothing and
publishes no portal content.
