## Client ownership and request flow

Native Activity/Compose UI -> DragonApi fixed HTTPS web origin -> explicit route policy -> web/main.py -> registered first-party identity/Personal API routes in api/main.py. Android does not own agent execution, provider credentials or business authorization.

DragonApi discovers mode and flags; do not fall back to compatibility after first-party cutover. Its route policy separates preauth and authenticated paths. Google Credential Manager receives a server-supplied challenge/client ID and returns a proof, not workspace authority. SecureSessionStore encrypts the authenticated cookie pair; SessionCookies retains only known realm-specific cookies. PendingAgentRequestStore keeps a session-bound marker, not prompts; do not replay unknown mutations. AgentRequestViewModel retains request outcome across Activity recreation without holding an Activity.

MainActivity bridges Java host code with Compose NativeChatView and immutable presentation state. UI actions still depend on API capabilities; shared design tokens and navigation components should be reused. AgentFileRepository validates file names and receipts and bounds transfer; inspect server authorization and readback before claiming real artifacts. NativeVoiceSession owns foreground WebRTC resource lifecycle; NativeVoiceView only presents it. No voice provider key belongs in the APK.

For every path, consult [tracked file inventory](../docs/codebase/FILE_INDEX.md) or generate the full source index. For runtime cross-boundary changes, consult [implementation flows](../docs/codebase/IMPLEMENTATION.md). The source and release gates, not this map, determine actual implementation and rollout.
