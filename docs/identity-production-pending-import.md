# Pending production identity import

This is an **operator-only** migration, not an application route. It cannot enable logins or transfer tenant authority.

1. Back up the Operly identity tables, and use a dedicated read-only export connection from an authorized runner. The destination must be the isolated DragonZpyder identity database with its imported-account activation CHECK intact and both relying-party clients disabled. No public database exposure, shared administrative credentials in the web API, or plaintext snapshot/logs.
2. Provide distinct source and destination connections using an approved secure secret store: `OPERLY_IDENTITY_EXPORT_DSN`, `DRAGONZPYDER_IDENTITY_MIGRATION_DSN`. The destination must be unused. The runner must reach both private database networks through an approved connection path; Railway's per-environment private DNS alone does not provide cross-project connectivity.
3. Review fresh aggregate account and explicit Google binding counts; run `python -m identity.production_import` from the API directory with those expected counts, the explicit pending-import approval argument, and the production import gate enabled in the migration-only process. This is a one-time insert-only transaction and no restart-based import. It never logs source rows. Verify completion counts and zero active accounts.
4. Keep all existing Operly account and business data intact. Preserve canonical UUIDs and compatible password hashes. Do not promote external channel bindings to login identities. Discord-only and other accounts without a supported login path must have a verified recovery or linking path before activation. Existing verified email alone is not sufficient to silently claim an account.
5. Pending imports must be reconciled again against the live source under a reviewed write freeze/delta procedure before activation; an approved inventory count is **not** a full snapshot digest. Add and validate Operly's existing-user federated mapping, new native personal-history import, and real A/B login/permission checks. No activation or source deletion is included in this change.
